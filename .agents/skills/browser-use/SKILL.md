Complete the requested task through the intended browser. Setup alone is not completion.

Use live tool schemas and instructions first, then documentation for the installed version. Treat old session commands, runtime names, paths, and errors as historical clues, not required interfaces or proof of current access. Resolve renamed or replacement tools by their documented capabilities; never re-enable a retired runtime to reproduce an old setup.

## Connect and prove access

1. Honor the requested browser and session. Select controls by their current capabilities: existing signed-in browser, isolated browser, or desktop control. If independent tab groups or pointer control matter, verify support explicitly. An isolated browser may need another login.
2. Discover available controls and read their setup instructions first. If missing, check tool discovery and the relevant installed integration once. Distinguish installed, enabled, exposed to this chat, and successfully callable. Use documented activation; do not construct private service bridges or impersonate a trusted runtime.
3. Make a lightweight supported call, such as listing tabs, then read the intended page. Confirm the site, relevant account, and visible content without exposing credentials. Use a dedicated task tab or group when supported; preserve existing user tabs.
4. Continue the requested scenario immediately. Reuse working bindings. After an update, explicit disconnection, or API mismatch, refresh discovery and relevant instructions, then repeat the safe access probe. Do not reuse old access proof across a changed runtime or session.

## Recover from the actual failure

| Observed failure | Next action |
| --- | --- |
| Missing tool or trusted runtime | Check documented activation. Identify the missing capability if unresolved; website login cannot repair it. |
| Extension or transport failure | Use the selected browser's documented diagnostics and recovery. Bound safe retries by its guidance; avoid unchanged loops. |
| Missing or stale tab | Refresh tabs or create a task tab in the existing runtime. Empty tab lists alone do not establish disconnection. |
| Login or MFA required | Start supported sign-in. Present any required human prompt while active, then resume. Never transplant cookies or profiles. |
| Denied or unavailable approval | Preserve the exact reason. Follow documented temporary-failure retries; an absent decision is not approval. Never bypass the gate through another surface. |
| Application error | Inspect the page and relevant diagnostics; distinguish product failures from connection failures. |

Use supported alternatives that preserve required identity, behavior, and authorization unless the user requires a particular route. Verify alternatives before claiming success. API reads can advance independent work but cannot prove a UI journey.

Request human action only for an evidenced requirement. Reuse existing authorization unless the tool requires reconfirmation. Explain the exact action and supporting evidence; avoid speculative setting changes, reinstalls, or reloads. Continue unaffected work while waiting.

## Finish with evidence

Verify the requested result in the live page, including persistence or readback when relevant. Inspect state before retrying uncertain submissions. Clean up task-created tabs and resources as authorized; preserve evidence and pre-existing work.

Report observed results and unverified parts. Distinguish current browser proof from earlier logs, setup checks, code review, and backend results. For blockers, give the failing layer, decisive error, and smallest supported next action without promising an untested fix.
